# RADA AI Website

A static, multi-page marketing website for RADA AI, built to the requirements in
`RADA_AI_Website_Development_Brief_for_Melvin.docx` and styled after the approved
reference site's visual language (navy/charcoal authority colour, restrained teal/electric
accent, serif display headlines over a clean sans-serif body, rounded cards, pill buttons).

## Quick start

```bash
npm run build   # regenerates every page from src/ into clean-URL output (/about/index.html, etc.)
npm run serve   # serves the built site at http://localhost:5173
```

There is no framework and no database — it is plain HTML/CSS/JS, generated by a small
Node build script (`build.js`) so the header, footer and cookie banner only need to be
edited in one place (`src/partials/`) instead of in every page.

## How the build works

- `src/pages/**.html` — the content of each page (just the `<main>` content, no `<head>`/nav/footer).
- `src/partials/header.html`, `footer.html`, `cookie-banner.html` — shared chrome.
- `build.js` — wraps every page in `src/pages` with the shared partials and the per-page
  `<title>`/meta description defined in the `pages` array at the top of the file, then writes
  it to a clean URL (e.g. `src/pages/about.html` → `/about/index.html`, so it's reachable at `/about/`).
- Editing `assets/css/style.css` or `assets/js/main.js` takes effect immediately — those are
  referenced directly, not copied.
- Run `node build.js` (or `npm run build`) after any change to a partial or a page fragment.

## What's implemented against the brief

- **Pages (Phase 1 scope, brief §17):** Home, What We Do, all 4 service-pillar pages, Solutions
  & Use Cases, About, Contact/Diagnostic, an Insights hub with 3 starter articles, and
  Privacy Policy / Terms / Cookie Policy.
- **Homepage story (§5):** hero → executive problem → Visibility/Control/Intelligence framework →
  four pillars → how RADA works (Discover→Prioritize→Design→Implement→Measure→Improve) →
  use-case examples → why RADA AI → a clearly labeled **illustrative** example (no fabricated
  client claims) → insights → final diagnostic CTA.
- **Conversion paths (§10):** distinct CTAs for the diagnostic, "Speak to RADA AI," a training
  proposal request, and "discuss a similar use case" — not just a single "Contact Us."
- **Diagnostic form (§10.1):** all fields from the brief, kept to one short screen.
- **Tone & trust (§11, §12, checklist):** no invented client names, quotes, logos or statistics
  anywhere on the site. The one "case study" section is explicitly labeled illustrative.
- **Technical basics (§13–14):** semantic headings, alt text on decorative SVGs marked
  `aria-hidden`, a cookie-consent banner, `sitemap.xml` + `robots.txt` generated on every build,
  per-page meta descriptions/canonicals/Open Graph tags, clean URLs.
- **Mobile-first (§9.4):** hamburger drawer nav, stacking cards, large tap targets — tested at
  375px, 768px and 1440px.
- **Visual direction (§9):** navy/charcoal + teal/amber palette, Fraunces (display) + Inter (body),
  line icons throughout, and hand-built SVG diagrams in place of the stock "robot/circuit board"
  AI imagery the brief explicitly asks to avoid.

## On replicating the reference site's exact WordPress/PHP/MySQL stack

The reference site runs on WordPress + PHP + MySQL + jQuery (per the technology lookup you shared).
Reproducing that exactly means a live WordPress install, which needs a local PHP + MySQL server
(e.g. XAMPP or Local by Flywheel) to run — that isn't something this sandboxed session can spin up
on its own, so this build is static HTML/CSS/vanilla JS instead, matching the same visual system.
Two realistic paths forward if a real WordPress CMS is still wanted (brief §13's "CMS the RADA team
can edit without a developer" requirement):

- **Convert this into a WordPress theme:** the CSS/JS/markup here can be ported into `header.php`,
  `footer.php` and page templates fairly directly, since there's no framework lock-in to unwind.
- **Keep it static and add a lightweight CMS:** point Insights at a headless CMS (e.g. Sanity) or a
  git-based CMS, so non-developers can publish articles without a full WordPress stack.

Either is a follow-on project — say the word and I can start on it.
